## 1. 方法

1. **裁剪**：`tools/crop_charts.py`（v2 已入库）
   - 默认 `bottom45`：裁底部 45%（覆盖 26228/26229/26230 多行，**含列位校准行**），缩到 ≤700px 宽提速

   - `full`：小图整图直送
2. **识别**：视觉模型 `deepseek-v4-flash-vision-exp`（provider deepseek1）
   - **校准提示**：把 26228=5,6,0,2,5、26229=2,8,0,5,4（万-千-百-十-个）真实开奖喂给模型，先对列位再读 26230 预测行

3. **对账**：与 `image_patterns_with_blogger.json` 中 hit=true 的旧记录逐条对比

## 4. 速度实测

| 轮次 | 图像规格 | 单图耗时 |
|---|---|---|
| R1 底部30%原尺寸 | 720-1024px宽 | 29s / 37s / 50s / 84s / 96s |
| R2 底部45%≤700px | 700px宽 | 40s / 40s / 68s / 101s / 126s / 140s / 183s |
| R3/R4 放大/全图 | 1080-1536px宽 | 14s / 33s / 35s / 50s / 51s / 370s |

- **缩小尺寸不能显著提速**：延迟主要来自模型对密集数字格的推理时长，波动 14s~6min，中位约 50s
- 并行 10 个 worker 时，33 张命中图全量复核墙钟约 3~10 分钟

## 5. 关键发现

1. **校准行是准确率的核心**：喂 26228/26229 真实开奖让模型先对列位，位置判定可信；放大 + 网格线 x 坐标可最终裁决列位歧义
2. **未来期幻觉风险**：模型会给 26231/26232（未来期）的空行填数字（实测读出"5,1,1,3,3"，与 500.com 最新仅到 26230 矛盾）——提示词必须声明"未来期应为空白，读到须存疑"，且**不得用于校准**
3. **辅助列陷阱**：部分图（富老师_3、默言言心_3/4）期号右侧有一列和值/辅助数值（13/15），万位实际在第2数字列——校准行自动识别，避免错位
4. **组合文字标注**："4++3 防9++8"、"38/27"这类居中横跨多列的文字是无位次组合标注，**不算定位命中**
